# 運用チェックリスト

教材PR作成・merge後の作業フローをまとめた運用メモ。
法令・判例の書き方ルールは `content-guideline.md` を参照。

---

## 1. 基礎演習教材型の目的

過去問演習前に、論点の入口感覚を作る教材。
正確な説明を全部載せるのではなく、スマホで軽く読めて、判例・場面・短い復習・ミニクイズへ自然につながることを優先する。

---

## 2. 基礎演習教材型の標準構成

| # | セクション | 備考 |
|---|-----------|------|
| 1 | 一撃定義 | 論点の核心を1文で |
| 2 | まずイメージ | ○/×の対比で直感を作る |
| 3 | よくある勘違い | 典型的な誤解を3項目で潰す |
| 4 | 判例を場面で覚える（または場面で覚える） | 場面・説明・結論の3層カード |
| 5 | 1分復習 | 覚えるフレーズ＋要点リスト |
| 6 | ミニクイズ | 択一式3問で自己確認 |
| 7 | 参考（折りたたみ） | 詳細・条文・試験ポイントを格納 |

---

## 3. やってはいけないこと

- 本文を長くしすぎない
- 新しい判例を安易に追加しない（source-logへの記録なしに追加しない）
- source-logなしの新規法的主張を追加しない
- 「必ず」「常に」など強すぎる断定を避ける
- クイズの正答インデックスを不用意に変更しない
- 確認状態を勝手に進めない
- `source-log.md` を不要に変更しない
- `human-check-tasks.md` を不要に変更しない

---

## 4. Codex Reviewの要否

### 必須にするPR

- 判例表現を触るPR
- 法的説明を追加・変更するPR
- クイズ正答や解説を触るPR
- `source-log.md` / `human-check-tasks.md` / `content-guideline.md` を触るPR

### 任意にできるPR

- 文言の軽微修正
- CSSだけの調整
- トップ導線の軽微な文言整理
- リンク文言だけの修正

---

## 5. merge後の役割分担

### Claude Codeが行う

- main pull
- 取得できる範囲でActions確認
- 公開URLと人間確認項目の報告

### Claude Codeが行わない

- GitHub Pages公開URLの実機確認
- Safari / Chromeでの表示確認
- クイズの実機操作確認
- 無理なActions深追い

### 人間が行う

- GitHub Actionsの成功確認
- 公開URLを実機ブラウザで開く
- スマホ表示確認
- タップ領域確認
- クイズ操作確認
- 読んで使いたい教材になっているかの感触確認

## 7. CSS変更時の確認ルール

CSSだけの調整は Codex Review 任意でよい。
ただし、スマホ実機確認は必須とする。

### 確認対象

- 表示崩れがないか
- タップ領域が確保されているか
- 横スクロールが発生していないか
- カード間隔が適切か
- 文字の読みやすさが損なわれていないか
